# 补充审计:REPLAN全部directive-bearing calls统计 + 措辞修正

对`ae_intervention_prompt_audit.md`的补充,仍是只读审计,不含任何代码修改。范围:sustained-only
134题运行(`ae_full_sustained_v1_a40_{practice,exam}`)全部15次REPLAN武装的**全部**directive展示窗口
(不再只看t+1/t+2)。

## 一、每次REPLAN实际持续了几个LLM call

用`active_patch_remaining_steps`(武装那一步的POST值)作为该次directive应持续的call数,并沿着后续
每个step逐一核实是否被新的武装(intervention_id变化,如severity upgrade或新事件)提前打断:

**15次里,全部15次都完整覆盖了3个LLM call(t+1、t+2、t+3),没有一次被提前打断或因episode结束而截断。**
`patch_duration_steps=3`在REPLAN这15次样本里是精确、无例外生效的,之前报告只看t+1/t+2遗漏了每次的
第3个call。

## 二、汇总统计(45次directive-bearing call,而非此前报告的30次)

| 指标 | 数值 |
|---|---|
| directive-bearing call总数 | **45**(15次武装 × 3步) |
| 格式合规率(有独立`Thought:`行,未把整段文字塞进Action) | **42/45 (93.3%)** |
| 明确重述任务目标次数(启发式关键词:"task is to"/"restate"/"the task:") | **13/45 (28.9%)** |
| 明确提出不同新路线次数(启发式:含"->"、"instead"、"first...next"等对比/顺序措辞) | **9/45 (20.0%)** |
| 重复"这个窗口内紧邻上一步"失败动作次数(与窗口内前一个真实action逐字相同) | **17/45 (37.8%)** |

**统计方法说明**:"重复失败动作"按窗口内**滚动比较**(offset=1时比较武装前触发那步的action,offset=2比较offset=1的action,offset=3比较offset=2的action),不是固定比较武装前的那一个动作——这样才能捕捉"模型在同一个3步directive窗口内自己制造的新重复"。"重述目标"/"提出新路线"是关键词启发式,非语义判断,数字仅供参考数量级,不是精确语义标注。

**格式违规的3次全部列出**(此前报告只举了2个具体例子):
- `look_at_obj_in_light-AlarmClock...` q=39 step=9 offset=2(窗口第2步)
- `look_at_obj_in_light-Pencil...` q=83 step=10 offset=1(窗口第1步)
- `pick_heat_then_place_in_recep-Egg...` q=7 step=3 offset=1(窗口第1步)

**"重复失败动作"的17次分布在9个不同的REPLAN武装事件里**,其中4次武装(Knife q=38两次、Mug q=64、
Pencil q=83两次、CD q=6、Potato q=20)在同一个3步窗口内出现了**连续两步动作完全相同**(offset=2和
offset=3都重复offset=1或彼此相同)——即窗口内最多3个call,有的窗口里model用了2/3甚至3/3的机会
在原地重试同一个已失败动作。

## 三、措辞修正(按你指出的三点)

1. **修正前**:"失败动作并非不存在"这类表述容易被误读成"prompt完全没有相关信息"。**修正后**:失败动作及其对应的environment反馈**确实存在于history里**(每一轮Thought/Action/Observation都完整回放,历史没有被截断——见原报告第三节),问题是**directive本身(静态模板)从未把"这一个具体动作"从历史里挑出来、明确标记为"这是刚失败的、不要再做"**——模型要自己从几十行历史文本里定位并识别出重复,这次统计显示45次里有17次(37.8%)模型没有做到这一点。
2. **修正前**:"当前状态缺失"容易被误读成"prompt里没有当前状态"。**修正后**:当前state的原始信息(最新一条Observation文本)**确实在prompt里**,只是以未经加工的自然语言形式存在,**没有一份结构化摘要**(比如明确写出"你当前在哪、手上拿着什么、最近3步分别做了什么、是否有效")去帮模型快速定位"现在到底卡在哪一步"——模型必须自己从原始文本重新推理这些信息,推理失败(或没去推理)就直接导致原地重试。
3. **修正前**:"两行格式与详细重规划要求存在结构性冲突"容易被理解成逻辑上完全做不到。**修正后**:45次里42次(93.3%)格式合规,说明**并非绝对做不到**——两行格式可以容纳一句压缩过的、带隐式列表的Thought(比如用"first X, then Y, then Z"这类紧凑表达);冲突体现在**当模型真的尝试执行"restate + discard + 构造2-4条子目标"这种更完整的表达欲望时(3次),更容易压不住冲动去写一段更长的说明**,从而突破"Action:"字段的单行预期,被解析成畸形动作。这是"格式对长表达不友好、诱发少数情况下的失败",不是"格式在逻辑上完全排斥简短计划"。

以上三处修正已经反映在下面即将实施的REPLAN prompt-v2设计里:v2会**程序化地把"刚失败的动作+其反馈"显式前置**,并**明确要求模型把复述目标+新路线+理由压缩进单独一行Thought**(用`A -> B -> C`这种紧凑记号,而不是要求真正的多行列表),直接针对上述三点。
